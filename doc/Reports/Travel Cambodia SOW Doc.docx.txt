Section 1: Introduction
A. Overview of the project
Welcome to Travel Cambodia, a platform created to help people explore tourist places in Cambodia easily. Travel Cambodia brings different travel information  to make users  find popular destinations, travel services and  prepare the plane.
Planning a trip can sometimes be confusing. To solve this, Travel Cambodia provides a catalog of tourist destinations such as Angkor Wat, the beaches, and food areas. Each place includes useful information, images, and details so users can see the destination before visiting.
Travel Cambodia also makes the platform easy to use. It includes an Itinerary Planner that helps users manage their trips day by day. Users can send booking or service requests such as tour guides, transportation, directly through the system. 
Overall, Travel Cambodia aims to make travel planning easier and more organized while still supporting local tourism. The platform helps users plan their trips and enjoy a more meaningful travel experience in Cambodia.
B. Purpose of the SOW
Our scope of work in this project points out to help the users carefree when they want to travel. Despite it benefits the users, it also boosts our country’s underdeveloped tourism sector. The project helps to build connections between the travelers and the tourism places to make both of them feel secured and ready to go as planned.
C. Project requirements
User registration and login: Users must be registered or log-in to the website before using the website.
User account management: Users should have the ability to customize their own profile and be able to manage their personal information.
User review: There should be a feature to let users give reviews or post about places they have gone to and experienced in the website. And the reviews should be displayed on the places.
Itinerary planner: Users can create their own travelling plan by scheduling the places they want to visit at certain times for a whole day.
Map Visualization: There should be a map that users can use to navigate to their locations.
Booking: Users can book on transportation, guides, hotels, restaurants and other places that provide services.
Performance: 
Recommendation Engine Latency: The recommendation system must process user preferences and return a list of suggested places in around 200–500 milliseconds.
Asset Loading: The contents and images must occur within 1.5 seconds when the user is on the website. 
API: The backend API must be able to handle at least 50 requests per second without crashing.
Security: 
Data Privacy & Authentication: Passwords must never be stored in plain text. They must be very secure and can only be accessed by the data administrator.
Usability:
Mobile Responsiveness & Layout: The UI must adapt to other viewing methods like for mobile, tablet and computers
Error Feedback: Error messages must be user-friendly in order for the user to know what’s going on instead of giving them technical terms.
Reliability & Availability:
Data Integrity: Database transactions for bookings must be “all or nothing events.” It means that if the user doesn’t go through the full process of the booking system, the booking session will be cancelled. This will help us get accurate data from the user.
Recoverability: The database must be saved and backed up automatically (every 24 hours). The system would be able to recover in 1 hour after any crashes.
Scalability: 
Database Scalability: The database tables must be properly stored in the database (e.g., indexing the Place_ID column). This ensures that searching for reviews remains fast (under 1 second) even when the database grows larger.
